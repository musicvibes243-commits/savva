# Как выложить этот сайт

Сайт статический: один `index.html`, папки с картинками и видео, никакой
сборки и никакого бэкенда. Отсюда всё и просто — разворачивается где угодно,
где умеют отдавать файлы.

Уже работает на GitHub Pages: <https://musicvibes243-commits.github.io/savva/>

Ниже — Vercel и свой сервер с доменом.

---

## 1. Vercel

Ничего настраивать не нужно: Vercel сам поймёт, что проект статический.

1. Зайти на <https://vercel.com> через **Continue with GitHub**
2. **Add New… → Project**
3. Найти репозиторий `savva` → **Import**
4. Ничего не менять: Framework Preset — `Other`, Build Command и Output
   Directory оставить пустыми
5. **Deploy**

Через минуту появится адрес вида `savva-xxxx.vercel.app`.

Дальше каждый `git push` в ветку `main` пересобирает сайт сам.

В корне лежит `vercel.json` — он только проставляет заголовки: неделю
кэшировать фотографии и видео, плюс пара заголовков безопасности. Страницу 404
Vercel подхватывает сам, потому что `404.html` лежит в корне.

### Свой домен на Vercel

Если домен уже куплен, его можно повесить прямо на Vercel, без своего сервера:
**Project → Settings → Domains → Add**, затем у регистратора прописать записи,
которые Vercel покажет. Сертификат он выпустит сам.

Но в задании нужен **свой VPS** — это следующий раздел.

## 2. Свой сервер и свой домен

Здесь потребуются деньги: домен и VPS платные. Ориентир — 200–1000 ₽ за домен
в год и 150–400 ₽ в месяц за самый простой сервер. Для статического сайта
хватает 1 ядра и 1 ГБ памяти, брать больше незачем.

Где брать: домен — reg.ru, beget.com, timeweb.com; VPS — timeweb.cloud,
beget.com, selectel.ru, из зарубежных hetzner.com. Система — **Ubuntu 24.04**.

### 2.1. Направить домен на сервер

У регистратора в настройках DNS создать две записи — вместо `203.0.113.10`
подставить IP своего сервера:

| Тип | Имя   | Значение       |
|-----|-------|----------------|
| A   | `@`   | `203.0.113.10` |
| A   | `www` | `203.0.113.10` |

Записи расходятся по интернету от нескольких минут до нескольких часов.
Дальше можно не ждать и настраивать сервер, но **шаг 2.4 (сертификат)
сработает только после того, как домен начнёт указывать на сервер**.

Проверить, дошло ли: `dig +short example.ru` — должен ответить ваш IP.

### 2.2. Поставить nginx и выложить сайт

Зайти на сервер по SSH (`ssh root@203.0.113.10`) и выполнить:

```bash
apt update && apt install -y nginx git certbot python3-certbot-nginx
git clone https://github.com/musicvibes243-commits/savva /var/www/savva
```

### 2.3. Включить конфиг

```bash
cp /var/www/savva/deploy/nginx.conf /etc/nginx/sites-available/savva
nano /etc/nginx/sites-available/savva      # заменить example.ru на свой домен
ln -sf /etc/nginx/sites-available/savva /etc/nginx/sites-enabled/savva
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

`nginx -t` обязателен: он ловит опечатку в конфиге до перезагрузки, а не после.

Уже сейчас сайт откроется по `http://example.ru`.

### 2.4. Сертификат, чтобы был https

```bash
certbot --nginx -d example.ru -d www.example.ru
```

На вопрос про переадресацию ответить **2 (Redirect)** — тогда http сам
отправит на https. Блок для 443 порта и продление сертификата certbot
настроит сам, руками в конфиг лезть не нужно.

Готово: `https://example.ru`

### 2.5. Обновлять сайт после правок

```bash
sudo bash /var/www/savva/deploy/update.sh
```

Скрипт подтягивает свежий коммит из GitHub, проверяет конфиг и перезагружает
nginx.

## Что проверить, когда всё поднимется

- главная открывается и видео на первом экране играет;
- переключаются три языка, на арабском вёрстка зеркалится;
- по несуществующему адресу (`example.ru/qwerty`) открывается своя 404,
  а не страница nginx;
- сайт открывается с телефона по мобильному интернету — это и есть проверка
  «а у других откроется».
